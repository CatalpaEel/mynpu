## 核对到的修改

- 1fb32ed / a5ac998：撤除外部 Host 与 GPIO；SBA 使用 XBAR master 3，CPU 数据与取指仍为其他 master。
- DM 支持 8/16/32 位访问、字节 lane 与总线错误上报；未增加 SRAM 端口，也未将 CPU halt 作为 SBA 的前提。
- 53655b5：互联改用 one-hot 数据选择、固定响应 lane，FIFO 增加 FPGA 分布式 RAM 映射。
- 上游有 CPU 持续运行、Vector 同时访存、1024 轮 SBA 读写的仿真记录，但其说明明确未复现旧实板故障。

因此新版本值得上板验证，仍需使用新镜像和不暂停 CPU 的 PC 路径检验，不能仅凭删掉 Host
宣布旧实板故障已修复。本轮对芯片 RTL 不做额外修改；改动限于 PC 工具、testbench 和说明。

## 本轮构建与仿真

本机重新构建，Vivado 2023.2，器件 `xc7a35tcsg324-1`，10MHz，8 线程，
area-medium、CPU RF LUTRAM、CNN DSP。布局后及最终输出必须通过默认 DRC 与 setup/hold。
冻结输入在 `npu/build/ego1-sba-53655b5-10m-20261115/source_manifest.json`，
Git 来源见同目录 `source_origin.json`。这与同学 Vivado 2025.2 的镜像是两次不同的工具运行。

本机最终资源为20048 LUT、13167 FF、4 RAMB36、56 DSP；setup +45.764ns、hold +0.030ns，
34024条可布线网络全部完成，默认DRC零Error。仍保留283项DRC Warning。
CDC结构报告另有19项异步复位Critical提示、2项缺失ASYNC_REG和263项握手使能Warning；
报告保留，不将生成镜像或功能仿真表述为CDC签核通过。没有为消除报告而改动芯片RTL。

ASIC 使用原 CPU RF、两块私有 RA1SHD 8KiB 宏的功能模型、50MHz；FPGA 使用
实际板级 wrapper、BRAM 与 CPU LUTRAM、10MHz。每种后端运行两次启动、各100帧，
逐帧比较全部十个整数输出、CPU分类和完成序号，检查最终完成票数。
运行期间逐周期断言 CPU 未 halt，并要求出现 SBA 与 CPU/NPU 请求重叠及实际 NPU 访存。
初始复位/装载阶段仍允许暂停 CPU。ASIC timing check 关闭，不做 PDK 签核。

## 实板顺序

1. 核对新板测包的 `kit_manifest.json`；只能使用本次新 bit/MCS。
2. 连接 EGo1 板载配置 USB，用 `program_fpga.tcl` 下载新 bit。
   只有一个 USB-A 时，先用 `program_flash.tcl` 对新 MCS 擦除/烧写/校验；
   再断电，JP2 选择 QSPI，用充电头供电，USB-A 改接外接 FT232H。
   通用 Flash 脚本按上次成功的命令整理，本轮实体操作仍需记录实际结果。
3. FT232H 按此前 Lab6 接到 J5，附加至 WSL，启动 OpenOCD；先用已验证过的100kHz。
4. 在板测包根目录运行下列命令。每次使用全新输出目录，失败即停止，无自动 halt 回退。

```sh
openocd -f npu/fpga/ego1/ft232h.cfg -f npu/debug/target.cfg \
  -c 'adapter speed 100' -c 'bindto 127.0.0.1' -c 'tcl_port 6666' -c init
```

在另一终端：

```sh
python3 npu/fpga/ego1/jtag_validation.py --assets assets --cpu-access running --mode smoke --timeout 120 --out results/running-smoke
python3 npu/fpga/ego1/jtag_validation.py --assets assets --cpu-access running --mode reload --boots 20 --timeout 120 --out results/running-reload
python3 npu/fpga/ego1/jtag_validation.py --assets assets --cpu-access running --mode continuous --runs 1000 --boots 2 --timeout 120 --out results/running-continuous
```

`--cpu-access running` 在初始上传后只通过 SBA 读写输入、mailbox 与结果，
禁止脚本在运行阶段发送 halt/resume/复位，每帧前后读取 DMSTATUS 检查 hart 状态。
OpenOCD 内存方式固定为 sysbus，不自动改用 progbuf。板上采样检查不能替代仿真的逐周期监测。

`--cpu-access halt` 仅用于显式对照，结果另存，不能计作并发路径通过。
十张已知输入的随机顺序不等同于完整 MNIST。主机往返耗时也不是纯 NPU 推理延迟。

本轮实体板结果在实际执行前保持 `physical_board_tested=false`。
