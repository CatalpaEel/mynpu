# Tiny MNIST 硬件部署

模型使用 `external/tiny_MNIST` 的 `pool-stride2-fp32-int8` 分支、提交 `22f3555`，直接读取已提供的 `outputs/pool-stride2-fp32-int8/model_int8.pt`，没有重新训练或重新校准。`artifacts/model.json` 保存 checkpoint SHA256、逐层 scale/zero-point、SRAM 地址及对比结果。本机运行原 PyTorch INT8 模型的全部 10000 张测试图，准确率为 **99.01%**。

硬件按原结构执行五层 3×3、padding=1 卷积和 144→10 全连接。Conv1/3/4 的 stride=2；Conv4 仅计算裁剪后保留的 3×3 位置，与先计算 4×4 再裁剪等价。中间张量采用 NCHW/CHW 连续字节布局，FC 权重采用输出通道优先布局。没有 MaxPool，Flatten 不搬运数据。

## 数值实现

checkpoint 的权重是逐输出通道有符号 INT8，激活是 affine **UINT8**。BN 已包含在 checkpoint 的融合卷积中。权重 zero-point 均为 0；导出器对这个条件及定点参数范围作检查。输入按 `(pixel / 255 - 0.1307) / 0.3081` 归一化，再使用 checkpoint 的输入量化参数。

每个输出通道存两个 INT32 定点参数：

```text
M = round_even(input_scale × weight_scale / output_scale × 2^24)
B = round_even(float_bias / output_scale × 2^24)
acc = Σ((UINT8_input - input_zero_point) × INT8_weight)    // INT32
q = round_even((INT64(acc × M) + B) / 2^24) + output_zero_point
```

卷积先将 `q` 下限限制到 output_zero_point 实现 ReLU，再饱和到 UINT8。FC 不执行 ReLU，饱和到 UINT8。边缘 padding 的实数为 0，相应乘加直接跳过。负数与正数均使用 ties-to-even。通道定点参数采用输出量化域偏置 `B`，不是传统 accumulator 域 INT32 bias。

这个 Q24 实现保留 checkpoint 的权重和所有 scale/zero-point，但与 fbgemm 的浮点重新量化不保证逐位相同。所选十张图有一处 Conv3 激活差 1 LSB，其余逐层激活及全部最终 logits 相同，十张分类结果全部一致。仿真严格逐项匹配独立 NumPy INT64 定点参考；上述 fbgemm 差异记录在 model.json 中。Q24 定点软件参考也已评估全部 10000 张图：准确率 **99.01%**，与 PyTorch 的分类结果差异为 **0/10000**。尚未对全部 10000 张图做硬件仿真。

## SRAM 与执行

SRAM 仍只有原来的 2048×32 位，未新增 ROM、RAM、FIFO 或张量缓存。

| SRAM 地址 | 内容 | 大小 |
|---|---|---:|
| `0x80000000–0x800003ff` | CPU 程序和六层描述符，入口 `0x80000080` | 1024 B |
| `0x80000400–0x8000135b` | 紧密打包权重及逐通道 Q24 参数 | 3932 B |
| `0x80001400–0x8000170f` | A 缓冲区，初始输入和最终十个量化 logits | 784 B |
| `0x80001800–0x80001b0f` | B 缓冲区 | 784 B |
| `0x80001f00` | CPU 写出的 argmax 类别 | 4 B |
| `0x80001f04` | 已完成层数 0..6 | 4 B |
| `0x80001f08` | 调试模式下 host 写的 layer ACK | 4 B |
| `0x80001f0c` | 0=正常运行，1=每层等待 host ACK | 4 B |

CNN 单元共享原矩阵单元的 NMC master 1，两个单元互斥。八路仲裁器、CPU 指令端和三通道 DMA 保持原设计。CNN 只有标量寄存器，一次计算一个乘加；乘法、偏置加法、舍入分别经过寄存器阶段。SRAM 读操作按字读取再选字节，写操作使用字节使能，不需要 read-modify-write。

外部主机先保持 CPU_CONTROL=0，用 RX DMA 将 `boot.hex`、`params.hex` 和 `inputN.hex` 装入上述位置，初始化四个 mailbox，最后写 `0x40000008=1` 释放 CPU。正常运行将 DEBUG=0，CPU 自动执行六层、比较十个输出 logits 并写类别。成功标志为 `0x40000004=0x600d0001`；固件错误为 `0xbad00001`。完成后可用 TX DMA 搬出十个 logits、类别或其他 SRAM 数据。现有 RX/TX 是 32 位 valid/ready/keep/last 原生流接口；具体板级物理接口由外层适配。

`sramN.bin` / `sramN.hex` 另提供完整 8192 字节 SRAM 镜像，含程序、权重、对应输入和正常模式 mailbox；可一次 RX DMA 搬入整个 SRAM 后释放 CPU。正常模式测试使用这一整片装载方式。

这些 hex 文件每行是一个字节，host 应按小端组装为 32 位 DMA beat，尾部设置 keep/last。CPU 使用对齐的 LW 及移位获取打包 logits，符合 NMC 地址对齐约束。调试模式仅用于逐层检查；正常模式的无需 ACK 执行也已单独测试。

## CNN MMIO

基地址 `0x40000600`。CONTROL bit0=start、bit1=clear；STATUS bit0=busy、bit1=done、bit2=error。新 start 清旧 done/error。描述符非法时置 error 且不访问 SRAM；忙时写寄存器/控制返回总线错误，当前任务继续。完成采用 STATUS 轮询，未新增 IRQ。

| 偏移 | 字段 |
|---|---|
| `00 / 04` | CONTROL / STATUS |
| `08 / 0c / 10 / 14` | 输入、权重、Q24 参数、输出 SRAM 基地址 |
| `18 / 1c / 20 / 24` | 输入宽、高、输入通道、输出通道 |
| `28 / 2c / 30` | stride、输出宽、输出高 |
| `34 / 38 / 3c` | 输入 zero-point、输出 zero-point、OP（0=conv，1=FC） |
| `40` | busy 周期数，只读 |

描述符均为完整 32 位寄存器并在启动时校验。基地址必须字对齐，张量内部按字节紧密存储；所有访问必须位于 8KB SRAM，输出不得与输入、权重或 Q24 参数重叠。卷积宽高 1..28、通道 1..16、stride 1 或 2；输出尺寸允许裁去底部/右侧。FC 宽度为输入元素数 1..144，高和输入通道为 1，输出宽高为 1，最多 16 个输出通道。跨 DMA/CPU/向量的内存冲突仍由软件管理。
