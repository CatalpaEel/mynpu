# CNN 数量字段改为 count−1：SD94

任务 FIFO 仍为 32bit，只修改低四位的含义：

| 位段 | SD94 定义 |
|---|---|
| [2:0] | count_minus_one，0～7 对应实际 1～8 个输出位置 |
| [3] | 保留，必须为 0；为未来配置上下文编号腾出的位置 |
| [6:4] | row_mask，不变 |
| [7] / [8] | 左 / 右 padding，不变 |
| [15:9] / [22:16] | x / y，不变 |
| [31:23] | 输出元素偏移，不变 |

硬件以 4bit 解码 `count = {0,count_m1}+1`，用于窗口范围、MAC 输出、部分和以及结束判断。因此编码 7 会执行八个位置，不会在三位加法中溢出成零。

C 的 `npu_stream_task()`、SV 的 `encode_task()` 仍接收实际数量 1～8，内部减一。它们对 0 或大于 8 的参数返回 bit3=1 的无效描述字；C 提交函数与硬件均拒绝该保留位。当前并未实现配置双缓冲，bit3 还不能作为实际配置选择位使用。

任务 ABI 从 SD93 的 `0x53443933` 升为 SD94 的 `0x53443934`，旧固件必须重生成。VPG3、Matrix 格式和共享卷积核方式不变，默认仍为共享 QT01 量化。生产镜像已更新。

验证见 `npu/reports/count-minus-one-validation.json`：边界 1～8、非法软件数量、保留位拒绝、深度 8/16 队列、CNN Stream、共享量化、单元流路由、IRQ/WFI，以及默认推理/逐层结果/JTAG。未重新测量面积或时序。
