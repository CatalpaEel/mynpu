# CNN 单任务支持 1～16 个输出位置：SD95

数量与容量保持不变；当前已[取消配置的忙时/排空写保护](software-owned-config.md)，下文原来的配置排空约束已由软件责任替代。

保持单套共享配置，不实现配置双缓冲。任务 FIFO 仍为 32bit，bit3 并入数量字段：

| 位段 | 当前定义 |
|---|---|
| [3:0] | count_minus_one，0～15 对应实际 1～16 个输出位置 |
| [6:4] | 三行输入有效掩码 |
| [7] / [8] | 左 / 右 padding |
| [15:9] / [22:16] | 输出起始 x / y |
| [31:23] | 输出元素偏移 |

不再有保留的配置选择位。输入、卷积核、几何参数和量化配置仍共享，允许运行中写入；软件保证与各读取/锁存阶段一致。

## RTL 和 RF 空间

数量解码使用 5bit，`count = {0,count_m1}+1`，因此编码 15 正确表示 16，不会溢出为零。位置、输出位置和部分和确认位置扩为 4bit；部分和占用标志从 8 位扩为 16 位。三行循环预取窗口和两个 seed 暂存槽保持原大小，沿任务逐步复用。

部分和存入现有 256B RF，总 RF 容量没有增加。每个任务按 `count × 4B` 检查部分和跨度，最多 64B；跨输入通道累加时使用这些槽位。配置 partial 地址时只要求一个对齐的 RF word 可用，完整任务范围在 START 时检查，所以同一个 RF 尾部 32B 空间允许 count=8，却会拒绝 count=16。

固件按每层最大任务大小预留部分和，而不是所有层固定预留 64B。当前五层 CNN 分别预留 56/56/28/12/12B，避免把原有 RF 中间结果挤到 SRAM。RF 权重暂存也遵守该区域边界。

## 软件接口与兼容性

- ABI 为 SD95 `0x53443935`，旧 SD94 固件需要重新生成，生产镜像已更新。
- `0x40000670` 返回 `0x00100020`：最多 16 个位置，32bit 任务。
- `npu_stream_task()` 与 SV `encode_task()` 是底层打包器，调用者须保证 count 在 1～16。
- `npu_stream_task_checked(..., &word)` 返回 0 或 -1，检查 count、坐标、掩码与输出偏移。正式 C 整行适配器使用它，并以最多 16 个位置分块。
- 低四位的所有编码现在都有合法数量含义，不能再用 bit3 作为“无效数量”哨兵；无效的 0、17 等软件参数由 checked 接口拒绝，而非伪装成硬件任务。

当前固件默认使用共享 QT01。14 个输出位置的一行从两个任务合为一个，CNN 总任务数由 296 降为 212。默认 8 项队列也可以容纳最多 128 个输出位置的一行分块，但张量地址、存储空间和数据通道所有权仍由软件负责。

## 验证结果

运行 `python3.12 npu/scripts/collect_count16_validation.py` 审核原始结果、依赖 SHA、端口宽度警告、生产固件可复现性及 C 检查；结果为 `npu/reports/count16-validation.json`。

验证包含 11 组 VCS 回归与 657 项 C 检查：

- 深度 8/16 的 32bit FIFO、单套共享卷积核、不同任务数量对应的部分和边界检查。
- 逐一覆盖 count=1～16、stride1/2、边界、未对齐行、RF/SRAM、count=16 且 cin=256。
- count=16 的三通道部分和，原始 INT32、量化 INT32/U8 的 RF/SRAM 结果，流输入与流输出反压。
- IRQ/WFI、单元间流转发、共享操作数读取。
- 默认推理 10 张图、60 个逐层张量共 17,940B 一致、JTAG 42 项检查。

默认共享量化推理从 **26,067 降至 23,937 周期/图**，减少 2,130 周期，约 8.2%。仍未达到 20k；本次未重新测量面积和时序。
